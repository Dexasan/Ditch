# DITCH security hardening - 2026-09-03

## Result and deployment state

This audit used the repository, the linked production Supabase catalog and auth configuration, production HTTP responses, a local production build, and targeted authorization tests. It does not establish whether a historical breach occurred.

**Applied live:** migration `011_security_boundary` and Supabase's minimum password length of 12. The migration was tested in a rolled-back transaction before application and recorded in `supabase_migrations.schema_migrations`. A subsequent catalog read confirmed the reduced grants.

**Implemented locally, not deployed:** HttpOnly auth/BFF, CSP changes, auth UI, CAPTCHA integration, realtime privacy/authorization changes, media token changes, relay health privacy, logging changes, and dependency upgrades. Existing unrelated media work was preserved outside this security branch. Guest credential plumbing needed by the secured LiveKit token request is included; media playback, screen-share audio and capacity-aware relay discovery changes are excluded. Deploy the backend changes with the web changes; the old password-token endpoints and old Agora wildcard audience UID are no longer supported by the updated API.

**Open launch gates:** create/configure hCaptcha; upgrade Supabase if native leaked-password protection is required; verify Agora co-host authentication and the media provider's removal/reconnect behavior; correct the Vercel Supabase URL environment value using valid deployment credentials. The new production password endpoints fail closed without a CAPTCHA site key/token, so do not deploy them before CAPTCHA is configured.

| Rotation and sign-out | Live rotation **already enabled**, reuse interval 10 seconds, access JWT expiry one hour. ### Plan to remove unsafe-inline

1. Generate a fresh cryptographic nonce in middleware for each HTML response; forward CSP and x-nonce into the request consumed by Next and put the matching CSP on the response. Preserve cookie-refresh writes and redirect headers.
2. Move HTML routes using nonces to dynamic rendering and disable shared HTML caching. Static pages can instead use build-generated hashes if their scripts are stable. Never cache/reuse a nonce across users.
3. Pass the nonce to explicit scripts and confirm Next's hydration scripts receive it. Include only the hCaptcha script/frame sources required by the configured provider. Begin with a report-only policy, then enforce script-src without unsafe-inline.
4. Inventory `style={{...}}`, style attributes, runtime CSS variables, RTC video sizing, canvas layout, and hCaptcha styling. Move static styles into CSS modules/classes; move truly dynamic values into nonce-authorized style elements/classes. Hash stable inline blocks where appropriate. A nonce cannot solve arbitrary element style attributes.
5. Exercise landing/auth, signup confirmation, protected pages, studio scene changes, Agora/LiveKit publishing, media playback and mobile controls. Enforce style-src without unsafe-inline only after that coverage. Keep frame-ancestors 'none' throughout.

## Priority 6 - Dependencies

The original pnpm audit reported **3 critical, 48 high, 33 moderate and 6 low affected dependency findings**; these counts are audit totals, not a claim of that many independently exploitable DITCH flaws. Notable paths included Next.js, Fastify/fast-jwt, Socket.io/Engine.io/parser/ws and media transitive Axios dependencies.

Updated Next.js to **15.5.25**, Fastify to **5.12.1** with compatible plugins, Supabase SSR to **0.12.5**, Supabase JS to **2.114.0**, and affected workspace dependencies. Removed unused @fastify/jwt, eliminating the unused vulnerable fast-jwt chain. Added patched-version overrides for affected transitives. Adjusted the auth page's async searchParams for Next 15.

Final `pnpm audit --json`: **0 critical, 0 high, 0 moderate, 0 low**. See [dependency-audit.json](dependency-audit.json). This reports registry-known advisories at audit time; it does not prove the absence of undisclosed flaws. The updated lockfile has not been deployed.

## Validation and reproduction

- `pnpm type-check`: all six workspace packages passed.
- `pnpm --filter @ditch/web build`: optimized production build passed.
- `pnpm --filter @ditch/api test:security`: eight tests passed, covering cross-owner mutations, guest publish authorization, queue privacy, ticket scope/tampering, removed-user requests and sign-out errors/JWT usage.
- In `apps/relay`, `node scripts/security-health.mjs`: bare health, protected detail, unknown paths and hostile-origin WebSocket rejection passed against an isolated relay process.
- `supabase/security-test.sql`: owner-A/owner-B isolation, direct participant/chat write denial, credential read denial, trigger execute denial and anon grants tested against production in a transaction that rolled back all fixtures before migration application.
- In `apps/web`, opt-in `RUN_LIVE_AUTH_TEST=true node scripts/security-session.mjs`: live Supabase refresh rotation, cookie flags, BFF response, CSRF and sign-out revocation passed; temporary user cleaned up. Do not run casually; it intentionally creates and deletes one confirmed test account without sending email.
- Browser: local production auth page rendered and switched modes with no console warnings/errors after removal of unsafe-eval. This is not full RTC end-to-end validation.
- Live catalog and auth settings were re-read after changes. Production HTTP evidence is in [public-probes.json](public-probes.json).

## Rollout checklist

1. Configure hCaptcha in Supabase and the web site key; verify missing/invalid tokens are refused by the direct Supabase Auth API. Confirm email callback allowlists. Native leaked-password protection requires a plan upgrade if desired.
2. Correct the Vercel Supabase URL value and provision matching RELAY_HEALTH_TOKEN secrets for API and relay. Include ditchlive.app and only the exact preview origins needed in WEB_URL. Supply NEXT_PUBLIC_LIVEKIT_URL/NEXT_PUBLIC_HLS_BASE_URL when used so CSP allows their exact origins.
3. Deploy patched API, realtime, relay and web together. RLS migration 011 is already live and registered. New cookies use a new name, so users reauthenticate. Do not deploy the web auth endpoints with CAPTCHA unconfigured.
4. Run authenticated studio/guest/anonymous audience tests, including backgrounded broadcasting, token renewal, participant removal and cached-token rejoin, across the actual media provider. Resolve the Agora co-host/removal or self-hosted LiveKit revocation gap before treating removal as an immediate server-enforced ban.
5. Verify production health, CORS/CSP, browser bundles, no client session tokens, and the nonce/style plan when that follow-up is implemented.
